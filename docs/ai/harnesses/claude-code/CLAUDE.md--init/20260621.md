# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Purpose

Template monorepo for .NET projects. Produces NuGet packages into `./output/`. Ignore placeholder files and projects — they are scaffolding.

## Tech Stack

- .NET 10 (`net10.0`) and .NET 9 (`net9.0`) via `TargetFrameworks` in `Directory.Build.props`
- C# latest language version
- Nullable reference types enabled globally
- Deterministic builds enabled
- Four test frameworks: XUnit (default), NUnit, MSTest, TUnit
- BenchmarkDotNet for benchmarks
- Cake for build orchestration
- Aspire for orchestration samples

## Build, Test, and Development Commands

All commands from repository root.

```
# Build all projects
dotnet build

# Build a single project
dotnet build source/business-domain-logic-models/HolisticWare.Core.BusinessDomainLogicModels/

# Run all tests
dotnet test

# Run a specific test project
dotnet test tests/unit-tests/UnitTests.XUnit/

# Run a single test (XUnit example)
dotnet test tests/unit-tests/UnitTests.XUnit/ --filter "FullyQualifiedName~ClassName_MethodName"

# Run benchmarks (Release)
dotnet run --project tests/benchmark-tests/BenchmarkTests.BenchmarkDotNet/BenchmarkTests.BenchmarkDotNet.csproj --configuration Release

# Clean and rebuild
dotnet clean && dotnet build

# Run Cake build script
dotnet tool restore && dotnet cake

# Cake targets (see build.cake and scripts/)
dotnet cake -t=libs           # Build source libraries
dotnet cake -t=unit-tests     # Run unit tests
dotnet cake -t=nuget-pack     # Pack NuGet packages
dotnet cake -t=samples        # Build samples
```

## Coding Style & Naming Conventions

- 4-space indentation. Allman style braces (`{` on a new line).
- **PascalCase** for public types, properties, methods.
- **camelCase with underscore** (`_fieldName`) for private fields.
- **Constants** are PascalCase (`MaxRetries = 5`).
- Interfaces start with `I` (`IRepository`).
- Nullable reference types enabled globally — use `!` or `?` explicitly where needed.
- Prefer `ArgumentNullException.ThrowIfNull()` over manual null checks.
- Run `dotnet format` to enforce formatting.

## Architecture

Clean Architecture layered approach:

1. **Domain Models** (`source/business-domain-logic-models/`) — pure entities and value objects, no dependencies.
2. **Utilities** (`source/utilities/`) — cross-cutting concerns (diagnostics, etc.).
3. **Infrastructure** (`source/infrastructure/`) — data access and database providers (PostgreSQL, SQLite).
4. **UI** (`source/user-interface-ui/`) — MAUI mobile apps, Razor/Blazor web components.

Dependencies flow inward: UI → Infrastructure → Utilities → Domain Models. Domain Models have zero internal dependencies.

## Testing

- Four frameworks supported: XUnit, NUnit, MSTest, TUnit.
- Test naming: `<ClassName>_<MethodName>_Should<ExpectedResult>`.
- Shared test code lives in `tests/*/common/` projects.
- Run all tests: `dotnet test`. Run a single framework: `dotnet test tests/unit-tests/UnitTests.XUnit/`.

## NuGet & Packaging

- Package sources configured in `NuGet.config`: local project output, user machine sources, nuget.org.
- Package source mapping restricts `HolisticWare.*` packages to local sources.
- Output directory: `./output/`.
- Build scripts: `build.cake` with fragments in `scripts/`.
